# H16 built-in HTTPS implementation plan

> Agentic execution: root builder follows executing-plans/test-driven-development; independent documentation work and a separate Astra security reviewer follow the owner handoff.

**Goal:** Opt-in HTTPS for the hub's UI and API, self-signed or operator supplied, preserving HTTP and Home Assistant ingress.
**Architecture:** Add TLS port 3443 to the existing nginx server through a startup snippet. Keep HTTP 3000 and backend loopback 8000; no duplicate routes, redirect, strict transport header, settings migration or UI toggle.
**Tech stack:** nginx, Python standard library SSL, OpenSSL CLI, pytest.
**Spec:** Program Phase 3 H16 and autonomous handoff; Jev selected nginx-opt-in with probability 1.0.

## Constraints and security focus

- Default mode off. Explicit modes self-signed/custom. Invalid enabled configuration fails startup.
- Self-signed SANs explicitly supplied as comma-separated DNS names/IPs (max 32); no container IP guessing. Persistent new data/tls directory, key 0600/directory 0700, atomic first creation, unchanged identity on restart. Reject partial/symlink state. Expired cert or missing requested SAN requires deliberate operator rotation.
- Custom PEM full chain and unencrypted key are read-only inputs; validate matching pair and current validity, never alter inputs. Path/SAN validation prevents nginx/OpenSSL config injection.
- TLS 1.2/1.3 only. Preserve nginx's scheme forwarding, Host including port, cookie and origin behavior.
- No built-in ACME: operators can use externally renewed certificates or existing reverse proxy. Self-signed warning bypass does not establish browser trust/PWA readiness.
- Work only in owned fb-wt worktrees. No merges, remote comments or release publishing. Use shared Docker roles and no per-job image builds.
