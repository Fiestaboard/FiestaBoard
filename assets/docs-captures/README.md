# Docs captures — serialised app screens

Generated files. Do not edit by hand.

Each `.html` here is the real DOM of a FiestaBoard screen, serialised from the
app running against a mock board with seeded fixtures. The docs site renders
these with its `<AppShot>` component instead of PNG screenshots.

- **Produced by** `web/tests/generate-screenshots.spec.ts` (see
  `web/tests/lib/dom-capture.ts`), regenerated by
  `.github/workflows/docs-captures.yml` on any `web/` change.
- **Consumed by** `Fiestaboard/fiestaboard.github.io`, which receives them as
  `static/captures/` through `scripts/publish-docs.sh`.

## Why not PNGs

A screenshot goes stale silently. The committed Settings screenshot on the docs
site showed an untabbed page with a `Carousels` nav item long after the route
had grown eight tabs and been renamed to Collections — nothing failed, because
nothing was checking.

A capture also costs a fraction of the bytes and covers more cases. One file
serves light, dark, desktop and mobile: the theme is a class on the wrapper and
every colour resolves through FiestaUI tokens, and the app is responsive through
CSS breakpoints rather than JS branching. The whole set is ~448 KB gzipped,
against 6.9 MB of PNGs that had no mobile variant and were 1×, so soft on every
retina display.

## Determinism

These are committed, so a capture that varies between runs would churn the diff
and bury real UI changes. Nine sources were closed, taking a two-run diff from
24 differing files to ~0:

| Source | Fix |
| --- | --- |
| Server-minted entity UUIDs in seeded fixtures | Renumbered in first-appearance order |
| React `useId` values | Renumbered the same way — they follow render order, so an inserted component would renumber everything after it |
| Live clocks — Settings shows `Right now: 1:38 PM` | `page.clock.setFixedTime` before navigation |
| Boards captured mid-flap (a flipping tile renders extra leaf elements) | Wait for `data-is-transitioning` to clear before pausing the clock |
| The Animations card's perpetual demo board | The app's own `board_animations: "off"`, which un-schedules its interval — and makes every other board snap to target |
| Transient toasts | Removed from the DOM |
| The remote-driven "Update available" banner | Removed — it reports whether a newer release exists, so every release would rewrite every capture showing it |
| Server-computed variable samples in the picker | Removed — the browser clock cannot reach them |
| Stray focus (the editor highlights the caret's gutter line) | Blurred before reading |

`reducedMotion: "reduce"` is set in `playwright-screenshots.config.ts` for the
same reason. It does not remove real board content: `/` and `/pages` still
render all 132 tiles with it on.

Screens that never settle on their own are marked `alwaysAnimating` in the
manifest. That is informational — the clock is pinned and advanced by a fixed
span, so the sample is taken at the same virtual instant every run.

The workflow captures twice and diffs. It **warns** rather than fails today;
promote it to a hard failure once real runs come back quiet.

## Anchoring

`manifest.json` records a `frame` selector for shots that targeted an element.
The docs site crops and highlights **by CSS selector, never by pixel box** — a
card can move four hundred pixels down the page and the crop follows it. Prefer,
in order: the app's own deep-link ids (`#instance-name`, `#timezone-picker`),
FiestaUI's `data-slot` attributes, then heading text.

Which means: **an id or `data-slot` a docs page anchors to is part of the
contract.** Renaming one is a docs change too.
